
## 거절 사유 해석

Google이 지적한 "게시자 콘텐츠가 없는 화면"은 실제 콘텐츠가 없는데 광고 스크립트가 로드되는 페이지들입니다. 쇼미룩의 경우 아래 페이지들이 해당됩니다.

### 원인으로 추정되는 페이지들

1. **로그인/인증 화면** (`/auth`) — 폼만 있고 콘텐츠 없음
2. **로딩/생성 대기 화면** (`/style` 생성 진행 중 상태) — 스피너/진행바만 표시
3. **404 페이지** (`NotFound.tsx`) — 오류 안내만
4. **결제/구독 리다이렉트 화면** — 이동 목적
5. **설문 응답 완료 페이지** (`/survey/shomi`) — 알림/확인 목적
6. **프로필 설정 화면** (`/profile-setup`) — 입력 폼
7. **팝업/모달만 있는 진입 화면**
8. **빈 갤러리 상태** (마이갤러리에 생성 이미지 0개일 때)

현재 `index.html`의 `<head>`에 AdSense 스크립트를 넣어서 **모든 페이지에서 무조건 로드**되기 때문에, 위 콘텐츠 없는 페이지들에서도 광고 요청이 발생 → 정책 위반으로 판정된 것으로 보입니다.

## 수정 방안

### 방안 A (권장): 콘텐츠 있는 페이지에만 광고 로드
- `index.html`에서 AdSense 스크립트를 **제거**
- 콘텐츠가 충분한 페이지에서만 스크립트를 동적으로 주입하는 `AdSenseLoader` 컴포넌트 생성
- 허용 페이지 목록: `/` (랜딩), `/community`, `/look/:id` (개별 룩), `/user/:id` (유저 갤러리), `/pricing`, `/pitch`, `/promo`, `/install`
- 제외 페이지: `/auth`, `/profile-setup`, `/profile-edit`, `/cart`, `/survey/*`, `/connect`, `/cafe24-fitting`, 404, 로딩/생성 중 상태

### 방안 B: 광고 슬롯이 실제 배치된 페이지에만 로드
- 향후 광고 단위(`<ins class="adsbygoogle">`)를 실제 삽입할 페이지에만 스크립트 로드
- 현재는 스크립트만 있고 광고 슬롯이 하나도 없는 상태 → 이것도 별도 위반 소지

### 추가 개선 (검토 권장)
- 404 페이지에 유용한 링크/추천 콘텐츠 추가
- 빈 갤러리 상태에도 랜딩용 소개 콘텐츠(예시 룩 등) 표시
- 팝업(ShomiChannelPopup)이 랜딩페이지 첫 화면을 가리는 시간이 길지 않은지 확인

## 구현 순서

1. `src/components/AdSenseLoader.tsx` 생성 — 현재 경로가 허용 목록에 있을 때만 `<script>` 태그를 `<head>`에 주입, 이탈 시 정리
2. `src/App.tsx`에서 `<BrowserRouter>` 내부에 마운트
3. `index.html`의 AdSense `<script>` 태그 제거
4. `public/ads.txt`는 유지 (필요)
5. 배포 후 Google AdSense 콘솔에서 "검토 요청" 재제출

## 확인 필요

- 광고를 실제로 노출할 페이지 목록이 위 권장안(랜딩/커뮤니티/개별 룩/유저 갤러리/가격/피치/프로모/설치)으로 괜찮은지, 아니면 특정 페이지를 추가/제외할지 알려주세요.
- 광고 단위(`<ins>` 슬롯)를 지금 삽입하는 작업까지 함께 진행할지, 아니면 스크립트 로딩 조건만 정리하고 슬롯은 나중에 배치할지 결정 필요합니다.
