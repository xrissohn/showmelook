# 실사용자 QA 실행 계획 (보고 전용, 제품 변경 없음)

## 현재 제약
지금은 계획 모드라서 계정을 만들거나 룩을 생성·저장하는 등 상태를 바꾸는 테스트는 실행할 수 없습니다. 그래서 이번 턴에는 테스트 결과를 하나도 보고하지 않습니다(PASS로 처리한 항목 0건). 이 계획을 승인하시면 아래 순서대로 실제로 실행하고, 한국어 상세 보고서를 드립니다.

## 원칙
- 제품 코드·설정·의존성은 수정하지 않고, 배포도 하지 않습니다. 생성 파일은 `/tmp/qa/`(스크립트·캡처)에만 둡니다.
- 인증: 내부 테스트 인증 기능(`lovable auth-session`)만 사용합니다. 계정이 여러 개면 기존 고객 계정은 고르지 않고, 앱 가입 화면으로 격리 QA 계정(예: qa+날짜@…)을 만들 수 있는지 먼저 여쭤봅니다. 토큰·비밀번호는 출력하지 않습니다.
- 실제 유료 이미지 생성은 최대 2회입니다(성공 1회, 필요 시 재현 1회).
- 하지 않는 것: 결제·주문, 외부 메일·SNS·방송 발송, 기존 고객 데이터 변경·삭제, 보안 공격, 타인 사진 접근.
- 실행 환경: 로컬 프리뷰(localhost:8080, 운영과 같은 백엔드 사용) + 운영 showmelook.com 읽기 전용 확인. 화면 크기는 데스크톱 1280, 모바일 390.

## 실행 순서
1. 정적 검사: lint / test / build 실행 결과를 기록합니다(파일 수정 없음).
2. 인증: 로그인, 새로고침 후 로그인 유지, 로그아웃 후 보호된 페이지로 리다이렉트되는지.
3. 프로필: 선택·입력값 검증(빈 값, 범위 밖 키·몸무게).
4. 스타일 요청: 추천 상품의 내용, 사이즈·옵션·재고 안내, 추천 변경/선택.
5. 이미지 생성(1~2회): 대기 화면, 완료 또는 실패, 생성 전후 크레딧/한도 변화.
6. 저장 흐름: 히스토리·갤러리 반영, 메모, 즐겨찾기.
7. 공개/비공개 전환 → 공유 링크 발급 → 로그인하지 않은 별도 세션에서 열람 → 비공개로 되돌린 뒤 차단되는지 재확인.
8. 장바구니 담기와 구매 링크 이동(결제 화면 직전까지, 결제 미실행).
9. 쇼미 채팅: 자주 묻는 질문, 스타일 질문, 정책 질문, 주제 밖·민감정보 질문 거절, 한국어/영어, `/shomi` 링크.
10. 가이드·요금제·설치·소개·규정 페이지: 한국어/영어, 모바일/데스크톱.
11. 정리: 제가 만든 QA 룩·장바구니 항목만 삭제하거나 비공개로 돌리고, 남은 상태(QA 계정, 사용한 크레딧)를 보고합니다.

## 보고 형식
케이스마다 다음을 적습니다.
- 실행 환경, 실제 입력, 실행 단계, 기대 결과, 관찰 결과
- 판정: PASS / FAIL / BLOCKED / NOT RUN
- 증거: 캡처 경로 또는 로그

결함은 1회 재현한 뒤 심각도, 사용자 영향, 개선 제안을 붙입니다. 이전 정적 점검에서 나온 세 가지 지적(공개 저장소, 서버 한도 검사, 아바타 경로)은 "정적 추론, 이번 실행으로 검증되지 않음"으로 따로 표기합니다.

## 테스트하지 않는 범위
관리자 방송, 실결제·주문, Cafe24 외부 상점 실제 설치, 외부 메일·SNS 발송, 보안 침투 테스트.
